A few weeks ago, I started to re-think how I organise my writing. Previously, I kept my writing in three folders:

* Drafts, where I intended to keep all my drafts;
* Writing, where all my writing, including my drafts, ended up, and;
* My website, which contains the final, published versions of my writing.

When I went to save a piece of writing, whether it was a draft, or something I was ready to publish, I would first save it in the “Writing” folder.

When I was ready to publish a piece, I would copy it from “Writing” to my site, make any edits (i.e. add images, add alt text, fix typos, re-work some of the post) and publish the edited piece. This system meant there was no easy way to find my drafts: they were all in the Writing folder, alongside the rest of my writing.

To address this problem, I set out to write a script that would look at all my files in Writing and move any pieces that were unpublished to the Drafts folder. Of note, my script could not compare files verbatim. This is because when I prepare a post for publishing, I add front matter metadata, and may have made some additions or changes to a post. I also couldn’t compare post titles, since some files in my Writing folder did not have a title, and some posts share a title. These considerations meant I needed to use an approximate matching system. For this project, I used [w-shingling](https://en.wikipedia.org/wiki/W-shingling).

I needed a script because there were many files to have to sort through. I also wanted something I could run at any point in the future should I continue not to put my drafts in the Drafts folder. Note that my script was not written to delete any files. **This was intentional; I didn’t want any coding errors I didn’t notice to delete any of my writing.**

My script reads all the files in my Writing and website folders. It then removes all special characters from each post, and splits up each post into sets of three words (shingles) like this:

```
into sets of
sets of three
of three words
```

These shingles are stored in a set (the data structure) for each post. This set maps to the file name in a dictionary, like so:

```
shingles = {
  "file1.md": {"into sets of", "sets of three"}
}

```

The shingles were stored as strings because lists cannot be serialised into an object a set can store in Python, the language I was using to write the script.

For each file in the Writing folder, which is stored in markdown, I open it, and compare its shingles to the content of every file in my website folder (the content here refers to the text that follows the front matter; this is ignored since it is not needed for the comparison). If over 70% of the shingles in the file match a file in my blog folder, the article is considered to be published. If no matches are found, it is likely the file represents a piece that has not been published. When this happens, the file is moved to my Drafts folder.

To generate the permutations for use in comparing files, I use:

```
from itertools import permutations
for a, b in permutations(shingles.keys(), 2):
...

```

Given `["Writing/file1.md", "Writing/file2.md", "Blog/file3.md"]`, this code creates a list like so:

```
Writing/file1.md Writing/file2.md
Writing/file1.md Blog/file3.md
Writing/file2.md Writing/file1.md
Writing/file2.md Blog/file3.md
Blog/file3.md Writing/file1.md
Blog/file3.md Writing/file2.md
```

The script only does comparisons if one of the two files is in Writing and the other is in the blog folder. As I write, I realise I should update my script so that, for example, the permutation `Blog/file3.md Writing/file2.md` would be skipped because `Writing/file2.md Blog/file3.md`, which refers to the same files, has already been evaluated.

When I ran this script, it was able to find many of my unpublished drafts and move them to the Drafts folder. There were some files that were moved to my Drafts that were actually published. w-shingling is *approximate*, and so this was expected. With that said, it did sort a good number of my posts, and enough for me to start feeling good about once again having a Drafts folder.

I am not going to share my final script since it is specific to my setup. With that said, I did want to write this up to show how I worked through the problem. If this post inspires you and you have questions, please don’t hesitate to [send me an email](https://jamesg.blog/email).
