Last weekend I attended the [10th IndieWebCamp held in the city of Düsseldorf](https://indieweb.org/2026/Düsseldorf). This is the second time I have attended the event, which was scheduled before the Beyond Tellerrand conference.

After the two days of talking about and making web pages at IndieWebCamp followed by two days of all things creativity at Beyond Tellerrand, I left with reams of notes. Both events always reminded me how many people there are out there making fun things on and with the web. For this post, I am going to focus specifically on the IndieWebCamp.

Day One: Discussions
----------

IndieWebCamp Düsseldorf is a two day event. The first day is structured using the [BarCamp style](https://en.wikipedia.org/wiki/BarCamp), which involves a day of discussions about topics that attendees want to talk about. I love this part of the event because you never know what you are going to discuss. Sessions are proposed by attendees, then organised by the people who proposed the session. Sessions this year covered topics from the HTML canvas element to what you should put on your website home page. [Notes are available for all the sessions](https://indieweb.org/2026/Düsseldorf/Schedule).

One of my favourite sessions of the day was “[What to blog next?](https://indieweb.org/2026/Düsseldorf/blognext)”, where we spoke about how we find inspiration for our personal websites. We covered everything from the stress of trying to publish every day as part of a challenge (something I feel a lot myself, which is why I tend to limit the number of challenges in which I participate and only do so when I feel comfortable), to the times of days we all write. As always, it was refreshing to hear how other people write and think about writing. I am not alone in my anxieties. Indeed, the feeling of community is what makes the event: you can talk openly about anything related to personal websites.

I proposed and facilitated a session on private posts, a topic I have been thinking about for a while but really needed others’ perspectives on. Several attendees were interested in what private posts could mean for their websites, but we all mutually felt that there is technical work to do to figure out what private posting would look like. I might try and start more discussions about this topic in the future because I think it is important. Not everyone wants to publish something publicly on the web.

Create Day
----------

Following the Bar Camp-style discussions on Day One, we went into Create Day. Create Day is a full day to make things. Often, the previous day of discussions inspires ideas. I had a few ideas in the back of my mind before going to the conference. The one at the top of my list was to fix the footnotes on my website.

The way that my site turns Ghost’s HTML representation of a post into files ready for my static site generator meant that the markdown-style footnotes I manually add to a post could not be computed by the library I use to process markdown. It took about an hour and a half to fix the problem. Now, when a post is retrieved from Ghost and saved to the disk for use with my static site generator, footnotes are put on a new line, a requirement for the markdown processor. This is all a bit convoluted and there are probably optimisations I could make, but for the weekend my priority was fixing the footnotes. Which, I can report, I did successfully!

After finishing my footnotes work – which took way longer than expected! <sup class="footnote-reference" id="f-1"><a href="https://jamesg.blog/longform-feed#1">1</a></sup> – I wanted to focus on a more fun project that I thought of just before Create Day: [Cat Chat](https://jamesg.blog/cat-chat), a way to chat with my blog mascot, [MJ](https://jamesg.blog/mascot).

The idea started with a note:

> CatChat — a web page that lets you chat with a cat and it sends a response with a photo of a cat or a meow etc.

Cat Chat is a single HTML file that has a text input field and a chat history. You can ask MJ a question and they will respond. All of the responses are based on some JavaScript code I write which looks for the similarity of an input question to a series of pre-programmed responses. If there is a pre-programmed answer, MJ will return it; otherwise, MJ will return their own random response: a meow here, a purr there.

Demo time
----------

At the end of the day, we all demoed what we made. This included people in the room as well as remote participants who had joined us to create something on their websites and share it with everyone attending.

In the minutes before demos began, I realised that I had a few things to share, including two things not already described in this post: an nginx configuration change and an update to my seasonal emoji script. I decided to make a [web page to list what I wanted to demo](https://jamesg.blog/iwc-dusseldorf). But I didn't want the list to show everything all at once, so I created the list using CSS checkboxes. When a checkbox is toggled, the next list item is displayed.

This is done using the following code:

```
li {
    display: none;
}
li:first-child {
  display: block !important;
}
li:has(input:checked) + li {
  display: block !important;
}

```

The `!important` statements may not be necessary, but I only had a few minutes to make this page before demos were set to begin! The last CSS rule is where the magic happens. It dictates that if an `li` has an input with the `:checked` state, the next `li` should be displayed.

I loved watching all the demos. Jakob experimented with representing concerts they want to attend on their website; Jo created an amazing terminal-based UI for updating her website; Bearina worked on a redesign of her website; Tantek improved his date archived pages. [We have notes on all the demos](https://indieweb.org/2026/Düsseldorf/Demos).

Collectively, we had wonderful discussions, fixed bugs, wrote blog posts, made web pages, designed and re-designed, improved parts of our websites, and more. I couldn’t have hoped for a better weekend.

On my trip, I purchased a Lucky Cat from a shop in the Little Tokyo neighbourhood of Düsseldorf. The energy of this cat stuck with me for, whenever I saw a picture of a cat somewhere – of which there were many! – I would say to others “look, a cat!” with glee. I thought a photo of the cat would be a fitting end to this blog post: a wave goodbye to the last IndieWebCamp, and a pre-emptive wave to the next one.

I learned a valuable lesson: always check that your code is actually running on the data. I was trying to fix a bug on a specific blog post and realised my code wasn’t touching the post because the post was on a different page of data. After I added pagination to look back to older posts in Ghost, my code worked as expected. I think figuring out the pagination issue took about a third of the time I spent on the footnotes project. When I finally figured out the issue, I went “oh!” and had a smile on my face. The feeling of finally understanding why something doesn’t work is sweet.
