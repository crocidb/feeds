At [Homebrew Website Club this week](https://indieweb.org/events/2026-07-15-hwc-europe), [Thomas](https://vanderwal.net) mentioned the term “tag healing” during a discussion about tags. The definition I caught was that tag healing is related to reviewing and, if necessary, consolidating, tags used for blog posts or documents. Someone ([Tabitha](https://tabitha.computer)?) said that “tag healing” sounded like a superpower, which inspired me to ask: if you could have a website-related super power, what would it be?

At first, I wanted my superpower to be instant recall of all the URLs on my website, such that I would be able to find the document relevant to a discussion or blog post immediately. As the discussion progressed, I expanded this idea, thinking it would be cool to be able to remember the URL of any web page. To be more precise, I would want to remember the URL of any web page I had visited.

Today I had an idea for another superpower: to be able to turn soups of un-semantic HTML into semantic HTML. This superpower would have to embody both the actual practice of changing the code (something I can do for more simple sites, and a skill I am always looking to get better at) with being able to instantly convince someone to change their site to have more semantic HTML.

Hey, maybe I have that superpower? Let’s give it a try. Herein, I cast “semantic HTML!” If you have some HTML you could make more semantic, consider if you could do so today! <sup class="footnote-reference" id="f-1"><a href="https://jamesg.blog/longform-feed#1">1</a></sup>

I wanted to extend the question to readers here: if you could have a website-related super power, what would it be? [Let me know.](https://jamesg.blog/email)

<sup class="footnote-definition-label" id="f-2">1</sup>

In this spirit, I started to clean a lot of unnecessary code on my home page, although my edits were mainly related to code cleanliness and not as related to semantics.
