Since the release of [Artemis](https://artemis.jamesg.blog), the settings page has been growing steadily in size. What was a few options has grown into over a dozen. With every added option, it was harder to find each individual option.

The new settings page
----------

With that in mind, over the last few weeks I have been working on reorganising the settings page into several sub-pages. Each sub-page relates to a particular part of a user’s account, such as account settings (i.e. email and timezone), reader preferences (i.e. how many days of posts to show in Artemis, how often to poll for new posts), night mode (disable Artemis during the night), and more.

Here is what the new settings page looks like:

![The account preferences page showing the user's registered email and domain name, email verification status, a banner indicating they are a supporter, and a list of links to sub-pages.](https://editor.jamesg.blog/content/images/2026/05/settings.png)

Each sub-page is listed on the main account management page. Each sub-page has an icon that corresponds to the purpose of the sub-page. <sup class="footnote-reference" id="f-1"><a href="https://jamesg.blog/longform-feed#1">1</a></sup>

Breadcrumbs on sub-pages
----------

When you click on a link, you are taken to the corresponding sub-page. The sub-pages all have breadcrumbs which makes it easy to go back to the original account settings page. Here is an example of the breadcrumbs on the “Holiday and Break Mode” settings page:

![The Holiday and Break Mode page with a breadcrumb under the main site navigation that has two links: Account Settings and Holiday Mode Settings.](https://editor.jamesg.blog/content/images/2026/05/breadcrumb.png)

ALT

The Holiday and Break Mode page with a breadcrumb under the main site navigation that has two links: Account Settings and Holiday Mode Settings.

The code for the breadcrumb component is based on the [Web Accessibility Initiative’s breadcrumb example](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/examples/breadcrumb/), which creates a region with the ARIA label “Breadcrumb” that can be announced to screen readers as a landmark. The `aria-current=“page”` attribute allows screen readers to know which page in the breadcrumb is the one they are viewing. I use the CSS `:after` pseudo-class to add arrows between each breadcrumb so that they are not announced by screen readers.

More changes: Checkboxes and Artemis Labs
----------

While I was reorganising the settings page, I also made the checkboxes bigger so that they are easier to click:

![Three options on the Artemis Reader Preferences page, each with a label on the left and a corresponding large checkbox on the right.](https://editor.jamesg.blog/content/images/2026/05/checkboxes.png)

ALT

Three options on the Artemis Reader Preferences page, each with a label on the left and a corresponding large checkbox on the right.

I also moved all of the experimental features into a new Artemis Labs section on the Reader Preferences page:

![A sub-section with the title Artemis Labs with two options. Each option has a label, a checkbox, and a corresponding description.](https://editor.jamesg.blog/content/images/2026/05/readerpreferences.png)

ALT

A sub-section with the title Artemis Labs with two options. Each option has a label, a checkbox, and a corresponding description.

Having a dedicated section for experimental features allows the interface to more clearly convey which options are experimental, in addition to the inline `(experimental)` tag in the label of each option in the Artemis Labs section.

Conclusion
----------

For a piece of software as customisable as Artemis, it is important for me that the preferences are as easy to navigate as possible. I still have things I want to change in the new interface, but for now I am happy with the new design. The settings page is less overwhelming now that each form has its own page.

If you have any feedback or notice any bugs on the account settings page, please contact me at artemis@jamesg.blog.
