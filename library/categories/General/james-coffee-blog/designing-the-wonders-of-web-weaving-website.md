When I started the [Wonders of Web Weaving project](https://web-weaving.jamesg.blog), I knew I wanted the technical design of the website to be web-first. This meant that the website would be the home of the project, where all episodes are published, publishing an RSS feed that people could use to listen to episodes.

In this post I am going to discuss a few of the technical decisions I made as I designed the project website.

Site architecture
----------

I wanted to have a separate website for the episodes, as opposed to using my main blog to publish episodes. A separate website could have its own identity: cover art <sup class="footnote-reference" id="f-1"><a href="https://jamesg.blog/longform-feed#1">1</a></sup>, colour scheme, and, generally, design. In addition, having a separate website meant that there was no risk that making changes to my main site – for example, changing styles, or the full design – would interfere with the page design for episodes for the show.

As a result, functionally, the Wonders of Web Weaving website is implemented as an independent, statically-generated website. I use the same custom static site generator that I use for my main website to run the podcast website. Because the site is static, the maintenance burden is relatively low; there are no back-end processes aside from the web server itself I have to manage. I also use a similar theme to my main website, although the Wonders of Web Weaving stylesheet is also independent from my main site.

Subdomain and permalink design
----------

With the intent to have a separate site in mind, I did wonder whether I should register a domain name for the project. I ended up deciding that I wanted the show to be on a subdomain of my main site. This approach meant that I would not have to register a separate domain name that I would have to renew every year. The subdomain I chose was `web-weaving.jamesg.blog`. Because the subdomain contained a dash, I decided to also set up `webweaving.jamesg.blog` so that, if someone typed the domain without the dash, they would still be directed to the right place. This is an example of “[forgiving design](https://jamesg.blog/2024/11/28/forgiving-interfaces)”.

I designed the episode pages to have simple permalinks: the path of each episode was its episode number. For example, the first episode – my interview with Adam from omg.lol – had the path `/1`. This permalink design pattern was appropriate because all of the episodes had numbers. With that said, in retrospect, a more descriptive permalink may have been useful to have as the main one (e.g. `/adam-omg-lol`), to which the numeric link (`/1`) could redirect. This is because `web-weaving.jamesg.blog/1`, when linked to someone in, for example, a message, doesn’t communicate as much information as `web-weaving.jamesg.blog/adam-omg-lol`. I don’t plan to change the design now, though.

Designing the episode pages
----------

The [episode pages themselves](https://web-weaving.jamesg.blog/25) have four sections:

1. The episode blurb.
2. An `audio` element that points to the `mp3` of an episode.
3. A heading describing who transcribed the episode, and;
4. The transcript itself.

Thanks to Zachary adding timestamps for when each speaker took their turn, I was able to add direct links to different parts of the episode. I described how this works in “[Writing a regex for adding links to time stamps](https://jamesg.blog/2026/05/25/time-stamp-regex)”. I am glad I wrote that blog post because I ended up copying that regex every week after I wrote it so that I could apply the regex to the week’s episode.

Because the project uses a static site generator, every episode has a markdown file with metadata, below which the transcript was stored. This metadata is used both on the website itself, and to generate the corresponding RSS feed, available at `/episodes.xml`. Here is an example of what the metadata looks like:

```
---
permalink: /17
title: "#17: James (jamesg.blog)"
layout: post
categories: ["Episodes"]
duration: "63:36"
length: "65610818"
audio_url: /assets/james.mp3
description: "In Episode 17, Mike interviews James, the author of 'with words, wonder' (formerly James' Coffee Blog) about, among other things, identity and personal websites, writing on the web, communicating the potential of personal websites, and more."
---

```

Below the metadata would appear the episode introduction with links to the guest's website, audio element, and transcript.

I copied the metadata from the previous episode to use as a base for formatting the next episode. This meant that sometimes there would be errors (e.g. the description might say episode 17 but the title says episode 18). I identified these quickly, but this is where a more automated process would have been helpful. A few months ago, I wrote a `Make` script that generates a markdown file with blank fields for my blog publishing flow. If Wonders of Web Weaving resumes in the future, I might look at writing a similar script.

*One note on this is that the `length` attribute is supposed to be the episode’s file size in bytes. I always forgot to fill this in and so all the file sizes appear the same, I think using the file size of the first episode. One day I need to go back and fix this because all the episodes do not in fact have the same file size.*

Conclusion
----------

I wanted to write all this down because I put a lot of thought into how to design the podcast website. If you have any questions, please don’t hesitate to [send me an email](https://jamesg.blog/email). Note that the source code to this project is not open, but you are always free to inspect the HTML to understand how each page and the main feed is structured.
