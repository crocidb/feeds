*Saccharide. Aries. From the vineyard. North or south.*

For fellow Swifties, these words will hold a special significance. For the purposes of this blog post, this collection of words are why this post exists.

The inspiration
----------

I read on Reddit that the aforementioned words contain the letters that spell out ENCORE. This was, I think, shortly before The Life of a Showgirl Encore was announced. I can’t find the exact source, but [this comment sums up the logic](https://www.reddit.com/r/TrueSwifties/comments/1wq9xrb/comment/pc36xp5/):

>
>
> She released her 3rd handwritten letter. So 3rd letter.
>
>
>
> SaCcharide ArEs FrOm ThE ViNeyard NoRth
>
>
>
> CEOENR unscrambled is ENCORE haha
>
>

This is a bit of a stretch – you could make so many words with those letters – but, admittedly, I was stretching a lot to figure out what the letters could mean, and so the finding (at least in hindsight) makes sense.

The project
----------

Back when the clues were released, I wrote Python code to do letter substitutions to see if I could find any words. I didn’t find anything. I did not think, however, about a program that took all the letters in the words and looked for any words that could be made from those letters. That inspired this evening’s programming.

This evening, I wrote a script that, using the letters from the “seed” words “Saccharide”, “Aries”, “From the vineyard”, and “North or south”, finds any words that can be made with those letters. My search turned out 38,046 results, using the macOS UNIX dictionary on my computer as reference in `/usr/share/dict/words` (which, I should note, contains combinations that are not really words but may be abbreviations, like “sma” and “asem”; a reduced list would have been more effective in getting a more reliable count).

Given the limits of this file, I don’t consider the number to be of any significance beyond the fact that the number of words that can be made up of letters from the seed words is high. Which is to say this approach probably would not have led to any revelation had I have used it, but, nonetheless, was fun to code.

Here is the code I wrote:

```
from collections import Counter

words = " ".join([
    "Saccharide",
    "Aries",
    "from the vineyard",
    "north or south"
]).lower()

letter_counts = Counter(words)

with open("/usr/share/dict/words", "r") as file:
    search_space = [w.lower().strip() for w in file.readlines()]

found = set()

for word in search_space:
    letter_space = dict(letter_counts)
    letters = []

    for l in word:
        if l in letter_space and letter_space[l] > 0:
            letter_space[l] = letter_space[l] - 1
            letters.append(l)

    if len(letters) == len(word):
        found.add(word)

print(len(found))

```

Here is what the script does:

1. A string that contains all of the seed words is defined.
2. The letter counts for this string are computed (i.e. “n” appears once, “c” appears twice).
3. The list of words in the UNIX dictionary on my computer is loaded.
4. For each word in the dictionary (i.e. “coffee”):
   1. A copy of the letter count distribution for the seed words is created. This copy is created because the distribution will be muted.
   2. For each letter in the word (i.e. “c”):
      1. If the letter is in the letter counts (“c” is, because “c” is in “saccharide”), and its count is greater than 0, then the count is reduced by 1 and the letter is added to a list, `letters`. This means that a letter is “used up”, which means that if, for instance, a word needs three “c”s, given there are only two “c”s in the seed words, these conditions could not be met on the third iteration, since the two “c”s would have been used up.
      2. Otherwise, nothing happens.

   3. If the number of letters in the `letters` list is equal to the length of the word, the word can be made from all the letters.

5. The number of found words is printed.

The results
----------

Finding ENCORE in the mix in such a huge number of words or terms would have been like searching a haystack. With that said, the chances of finding a word could be improved by restricting the search space to Swift-adjacent words. This is obvious in retrospect – knowing that ENCORE – is in the letters, but not necessarily now.

As a method of finding a clue in the words, the brute-force approach is not necessarily appropriate. But, the result – a script that finds all words contained within a set of letters – is interesting. Using my script, for example, I can plug in other words or phrases, like “James”, which returns, among other results, “mesa” and “sea”. I had never thought about looking for other words in my name. Or “Lover” – one of Taylor’s album names – contains the letters you need to make “lore”.

Is this script revolutionary? Not really. Was it fun to make? Definitely! Did I solve any mystery? No. But do I feel good? Yes! I have been thinking about writing this code all week and I am glad I finally had some time to write the script.
