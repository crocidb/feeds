Last month I moved away from using the Ghost CMS to publish pages and posts on my website. I made the move because I realised I was maintaining more than I really needed to make my site work. I had to manage Ghost (and keep it updated) and an intermediary endpoint to which Ghost would send a web hook when my site was updated. This web hook would then trigger my static site generator. TL;DR: There were a lot of moving pieces.

Now, I use my static site generator on my laptop. I have a `Makefile` with a few commands to help me build and publish my site:

* `make blog` builds my site and uses `rsync` to publish my site.
* `make post` creates a post with the front matter I need, filled in with the post date.
* `make build` builds my site only.
* `make serve` builds and serves my static site.

In practice, I have only been using the first two commands for the most part since the majority of work I have been doing lately related to this site has been writing and publishing blog posts.

When I run `make post`, it creates a file in the format `YYYY-MM-DD-title.md`, where YYYY-MM-DD is the current date. `title` is a placeholder that I have to replace. This week, I published a post where I forgot to replace the placeholder, so the permalink was not representative of the post.

This inspired me to write a little bash script that runs before my site is generated and uploaded with `make blog`. This script checks for a post with a file name ending in `-title.md`. If such a post exists, the build process does not start. Instead, a message is printed to the console that says: “A blog post does not have a title”, followed by the name of the file to which this warning applies.

Here is the bash script I wrote:

```
for i in $(ls pages/posts/*.md);
do
    if [[ $i = *-title.md ]]; then
        echo "A blog post does not have a title."
        echo "    " $i
        exit 1
    fi
done

```

This is saved in a separate shell script that is called from my `Makefile`. The `exit 1` line makes the whole script -- including the Makefile command -- stop so that I can address the issue. I can then re-run `make blog` to build my site. <sup class="footnote-reference" id="f-1"><a href="https://jamesg.blog/longform-feed#1">1</a></sup>

This is an example of “[forgiving design](https://jamesg.blog/2024/11/28/forgiving-interfaces)”, where the system checks for a potential state that I don’t want – a post without an assigned permalink – and lets me know I need to do something before I can proceed with publishing.

My current setup is more technical than my last one, but there are many fewer parts to maintain and secure. I am sure I will be making little tweaks like the one described above to make the publishing process more streamlined and error-proof. Therein one of the many joys of making things: when I notice something that can be improved, I can make a little change and maybe even write about it for reference both for myself and others.

<sup class="footnote-definition-label" id="f-2">1</sup>

One edge case for this implementation is that I can't have a post whose permalink ends in -title. I will cross this bridge when I need to, likely by using a regex to validate that the form is YYYY-MM-DD-title, instead of \*-title.
